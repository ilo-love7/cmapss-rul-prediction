## 3 关键实现决定

1. **工况判定不能按 unique 原始值**：FD001 工况设定带 ±0.0087 噪声，`np.unique(round(op,4))`
   不唯一 → KMeans 伪聚类成 6 簇。改「round 到 1 位小数唯一行 ≤1 或 spread<0.05 → 单工况」，
   FD001/3 正确识别为 1 工况，FD002/4 为 6 工况。
2. **piecewise RUL 封顶 125**：业界惯例（训练引擎寿命 128–543 周期）。
3. **验证集按引擎划分**（20% 引擎）防泄漏——同引擎窗口高度相关。
4. **相似度匹配基线向量化**：初版把 `(n_test, window, d)` 当单个窗广播出了假预测；
   改为 sliding_window_view 批量算相关 + 逐测试引擎 top-10 加权。

### 7.2 三个新结论

1. **末窗 RMSE 会骗人**：滚动预测后临近失效 RMSE 4–10，早期 >200 真值 116–163；早期误差来自标签封顶（模型只能输出 ~125），按封顶真值算只有 13–16。**评估口径必须和标签口径一致**；运维要的"临近失效准不准"比头号数字好 1.5–3 倍。
2. **三模型集成 + 免费置信度**：集成宏 RMSE 13.72（最优单模型 14.05）；三模型预测 std 与误差显著正相关（ρ 0.14–0.49），三分位 MAE 严格单调（FD004: 6.2→11.0→14.8）。**模型分歧不需要额外训练就是可用的不确定性代理**。
3. **跨子集迁移是真掉点**（见 08 结果）：同协议下源域自测 13.96 → 迁移 21.14，oracle 12.95，缺口 +8.18——跨故障模式（HPC→HPC+Fan）的域偏移比跨载荷（N1）更难。

### 7.3 v1.1 踩的坑（新增）

12. **三分位掩码边界写错**：`std >= hi`（hi=inf）导致高三分位永远为空 → `TypeError: NoneType.__format__`。修法：第三段用 `std >= lo`。**教训：分位数分桶的最高段要用 `>=lo` 而不是 `>=hi`**。
13. **批量预测接口里残留"死函数"**：写 `06_rolling.py` 时先写了个带 `if False` 分支的 `load_model`，差点混淆。清理掉后用 `load_model2(stem, n_features, subset, cfg)`。
14. **迁移实验的 oracle 必须单独重训**：目标域自训（oracle）不能复用源域权重（预处理三件套不同），必须 `prepare(target)` 全流程重算 + 重训，否则"迁移缺口"会把预处理差异算进去。

## §9 v1.3 深化（2026-11-11）

### 9.1 新增模块与实验（12–15 四脚本）

- `intervals.py`：CQR 加成式（Romano 2019）、乘性缩放（归一化残差 (y−c)/h_side，单/双因子）、Mondrian 分层共形（层查表 + 小层回退全局）。纯函数。
- `adaptation.py`：CORAL（协方差差 Frobenius）、RBF-MMD（多带宽中位数启发式）、`train_da`（对齐损失挂 `SeqRegressor.encode` 的窗口表征，val RMSE 早停与 train_regressor 同口径）、few-shot 微调（deepcopy 不动原模型）。
- `online.py`：风险-覆盖曲线（AURC）、因果单调修复（前向 clip 到 −1≤Δr≤0）、自洽重标定（T̂=滑窗 median(pred+t)）、EMA。
- `12_two_stage_intervals.py`：复用 09/11 检查点，六种 90% 区间对比 + 校准分数分布诊断。
- `13_domain_adaptation.py`：三对迁移 × {plain, coral, mmd, fewshot k=5}，同 harness 内部基线 + v1.1 外部参照。
- `14_online_gating.py`：4 模型集成均值滚动 + pinball 宽度分数，后处理四变体 + 双分数门控 + 违反率诊断。
- `15_summary_v13.py`：汇总表。单测 28→73（`test_v13_intervals/adaptation/online` 45 项）。

### 9.2 结论（v1.3 三实验）

1. **二段缩放 = 免费保险**（§3.13）：FD003 欠覆盖 0.810 → 0.920（CQR Q=5.81 / λ=1.45），宽度 37 仍比共形-对称 57 窄 35%；FD001/002 已准时 Q=0/λ=1 原样通过。机制：cap 截断使校准分数在 0 上形成点质量（FD001 33%/FD004 43%），90% 分位落入点质量 → 不膨胀；分层共形全面劣于宽度自适应。
2. **在线后处理三件套全负结果**（§3.15）：单调修复把违反率 0.65–0.77 修到 0.000 但 RMSE +4~7%——诊断显示 43.6% 相邻对是向上修订、其平均误差 −28.0（负偏差下的修正信号），被约束禁止；门控分数与误差**负**相关（ρ −0.11~−0.54，早期 cap 饱和区低分歧大错），AURC 差于随机。
3. **域适应 = 边际对齐负收益、few-shot 有效**（§3.14）：CORAL/MMD 2/3 对劣于 plain（条件偏移下边缘对齐破坏条件结构）；few-shot k=5 在 FD002→FD004 缺口 23.95→4.71（关闭 80%），bias +20.4→+3.5。结论：缺口是条件映射偏移，不是表征错位。

### 9.3 踩的坑（16–18）

16. **`_src_kit` 收 Subset 对象炸 `sensor_matrix`**：`data[src]` 是 io 模块的 Subset 容器不是数组，要 `.train`。第一跑 12s 即炸，第二跑才是真数据。
17. **自洽重标定"恒定偏置不可区分"被当成 bug 猜了一轮**：pred+t≡T 的恒等式下，恒定偏置等价于另一个失效时刻——方法本身无法校正，不是实现错。单测改钉真实语义（去漂移/去野值）后全绿。负结果要先想清楚方法的可辨识性边界。
18. **拼接多引擎序列算违反率会混入引擎边界跳变**：必须逐引擎计算再平均；用 |Δ|<100 启发式分段是脆弱的补丁，直接挪进引擎循环才是对的。
